# img desktop

img 0.4 提供统一图床管理、两个独立单图工具、跨设备同步和文章引用维护。操作步骤见 [0.4 使用指南](../docs/0.4.md)，验证结果与限制见 [迭代记录](../docs/iteration-0.4.md)。

原生 Rust / GPUI Kit 上传界面，视觉来源为 [用户参考图](../design/reference-upload.png)。默认窗口优先使用 1360 × 900，小屏幕会预留桌面边距并缩小，最小 960 × 700；侧栏可收起，底部状态栏固定，内容区独立滚动。保留 macOS 原生红黄绿按钮，顶部工具栏空白处支持拖动。

## 运行

需要 Rust 1.98.1 和 macOS 的 Xcode Command Line Tools。已在 Apple silicon、Rust 1.98.1 上编译。

```sh
make desktop-preview  # 参考图示例：两张图片、87% 进度、示例容量
make desktop          # 真实本地队列
make desktop-bundle   # 构建 target/Img.app
make desktop-test
make desktop-package # 本地 DMG / ZIP（未公证）
```

应用的版本是 0.4.0。`--reference` 中的 128 张、SM.MS / Imgur 和容量按参考图显示，仅用于视觉预览。示例链接使用 example.com；模拟上传不进行网络请求。关闭参考预览后，通过不带参数的应用进入真实队列。

## 已接入的交互

单图处理直接位于左侧「转换与压缩」「尺寸与裁剪」，与图库、上传同级，不再有「图片工具」父入口。打开或粘贴一张图片后，两个入口共用当前图片和参数；更换图片会重置裁剪、旋转与翻转。多文件和文件夹不会批量导入。

转换支持 PNG、JPEG 和静态 WebP；PNG 保持无损，目标体积不会暗中改变格式或尺寸。尺寸工具支持缩放、裁剪、旋转与翻转。页面采用左侧预览、右侧参数布局；参数独立滚动，实际体积和保存、复制、上传操作固定在右下方。预览可复制为图片，也可以直接上传，无需先保存；保存后可定位文件，原文件保留。参数切换复用近期预览，实际输出体积由完整编码结果计算。当前里程碑与验收记录见 [img 0.4](../docs/iteration-0.4.md)。

- 文件选择、剪贴板和截图按钮位于拖放 / 粘贴区下方，与链接格式和「上传」按钮同一排。
- 左上角工具栏提供侧栏开关（⌘B）、后退和前进；侧栏使用图标导航，收起后完全隐藏并记住选择。
- 侧栏尺寸和导航选中背景使用可中途反向的弹簧动画，页面、筛选与网格 / 列表切换带短过渡；遵循系统减少动态效果设置。
- 每批最多 50 张，默认单张 8 MiB，可在设置调整为 1–128 MiB；支持 PNG / JPEG / GIF / WebP / SVG / AVIF。位图预览解码限制 2400 万像素；原图字节单独保留。SVG 预览不读取外部资源；AVIF 使用系统图像服务生成预览。
- 搜索文件名、目标存储和 URL；全部 / 上传中 / 已完成 / 失败筛选只出现在上传队列内部，不影响图库和历史记录。
- 图库支持网格和列表展示：网格突出缩略图，列表展示文件名、URL、存储源和大小；自动记住展示方式。
- 图库点击「选择」后可勾选图片，缩略图仍可预览。搜索和切换网格 / 列表会保留选择，操作栏显示选中总数与搜索隐藏的数量。「全选当前结果」追加所有匹配记录（含未滚动到的图片）；「取消全部」清空选择，「完成」或离开图库退出选择模式，重启不保留选择。
- 「复制所选」按图库原记录顺序复制全部选中项，包括搜索隐藏项；格式菜单支持五种现有格式，选择后立即复制并记住偏好。缺失链接会跳过并提示数量。「清理所选」确认框显示总数和隐藏数量，仅删除应用记录和缓存，保留原文件与远端图片；上传任务占用的记录受保护，保存失败不会删除缓存。
- 复制支持纯链接、Markdown 图片、Markdown 链接、HTML 图片及 BBCode。复制按钮旁的下拉菜单选中格式即复制，随后沿用该格式；队列、图库、历史及图片预览共用此设置。
- 上传支持 1–6 项并发，默认 3 项；暂停 / 继续、单项取消、取消本批、自动重试和批量重试失败项。默认完成后自动复制本批全部成功链接，按导入顺序换行排列。
- 进度来自 HTTP 请求体实际传输读取量，包含 multipart / JSON 编码开销，不把哈希、压缩或签名读取计算为上传。传输完成后显示“等待确认”，收到服务端成功结果后才标记完成；上传时锁定本批存储源、上传参数与复制偏好。
- 点击缩略图打开预览；Esc 关闭。⌘U 选图、⌘V 粘贴、⌘F 搜索、⌘⇧S 截图、⌘W 关闭、⌘Q 退出。
- 设置分为「存储源」「上传与图片处理」「链接与剪贴板」「应用偏好」「关于与更新」。存储源可新增、编辑、删除、测试连接和设为默认，支持 R2、S3、OSS、GitHub 与自定义 HTTP。HTTP 请求方法直接选择，额外请求头与表单字段使用键值输入；支持临时会话令牌、提交说明、路径形式访问和 HTTP 服务选项。
- 存储表单校验必填项、地址及重复名称。编辑时空凭据字段保留已有凭据，新凭据保存在 macOS 钥匙串，设置文件只存引用；写入失败会撤回新建的钥匙串条目。

- 链接按钮可导入远程图片，粘贴也识别多行 URL。下载成功后进入本地队列；遵循大小限制、同源重定向和 HTTPS 要求，可信 HTTP 来源需在设置开启。
- 上传设置提供 PNG / JPEG 压缩、缩放、JPEG EXIF / GPS 清理、并发数、重试次数、大小限制、目录、路径模板、命名和同名覆盖。需要处理 JPEG 时先应用 EXIF 方向，防止上传后旋转；动画与不支持处理的格式保持原始字节。
- 清理单条或全部已结束记录时显示确认范围，只删除应用内副本和记录，保留用户原文件及远端图片。
- 更新设置支持检查版本、下载并校验安装包。正式签名、公证、安装与 CI 配置见 [发行说明](RELEASING.md)。

## 数据与上传

原生界面通过应用包内的完整 Rust `img` CLI 使用统一上传后端；协议通过 JSON 结果与独立的进度事件传递。无需另外安装 CLI。独立 CLI 和 GUI 内置 CLI 都由 `crates/img-cli` 构建，共用 `img-core`；「关于与更新 → 添加终端命令」可将内置 CLI 链接到 `~/.local/bin/img`。使用 `install.sh --gui` 安装时会自动建立这个命令入口。

macOS 数据目录是 `~/Library/Application Support/aperture`，参考模式使用其 `reference-preview` 子目录；两者互不覆盖。调试可用 `APERTURE_DATA_DIR` 指定独立目录、`APERTURE_ENGINE` 指定测试引擎。

数据目录沿用此前预览版本的位置，避免改名丢失队列。`preferences.json` 原子保存展示与更新偏好；`upload-options.json` 独立保存上传参数；它们不会覆盖 `queue.json`。`--compact` 用于检查 960 × 700 布局，`--reference-size` 用于检查原图的 1280 × 1800 布局。

真实队列以原子文件替换保存，保留图片副本；示例数据不会写入队列。一个数据目录同时只允许一个进程。暂停会终止当前请求，继续时重新上传该文件，不是断点续传；不会删除服务端可能已经接收的图片。上传中关闭 / 退出可选择继续使用、完成后退出或暂停并退出。退出会终止并回收上传子进程，保存暂停状态，重启可继续。

应用自动管理全局 `~/Library/Application Support/img/config.toml`，保留已有存储源及无关设置。可用 `APERTURE_CONFIG_PATH` 指向隔离测试配置。每次上传生成仅包含所选存储源的 0600 临时快照，通过引擎的 `--config` 传入；工作目录也隔离，不读取项目 `.img.toml`。桌面端始终能读取 JSON 结果，无需用户修改原有 `output.quiet`。

新增凭据使用 `IMG_DESKTOP_*` 引用，桌面端从钥匙串读取后仅传给子进程；CLI 在 macOS 也能解析这些引用，环境变量优先。原有环境变量凭据保持兼容，队列不保存凭据。验收使用隔离配置和本地 HTTP 测试服务，没有执行真实云图床上传。
